# Mini-CRM распределения лидов

Небольшой сервис на FastAPI + SQLAlchemy + SQLite, который распределяет обращения лидов между операторами по источникам с учётом весов и лимита нагрузки.

## Модель данных

Используются следующие сущности:

- **Operator**
  - `id`, `name`, `is_active`, `load_limit`.
  - Связан с обращениями (`Contact`) и весами по источникам (`OperatorSourceWeight`).

- **Source**
  - `id`, `name`.
  - Связан с обращениями и весами операторов для этого источника.

- **Lead**
  - `id`, `external_id` — внешний идентификатор лида (телефон/email/любой уникальный идентификатор).
  - Может иметь несколько обращений из разных источников.

- **Contact**
  - `id`, `lead_id`, `source_id`, `operator_id` (nullable), `message`, `created_at`, `is_active`.
  - Факт обращения лида через конкретный источник, с назначенным оператором (если найден).

- **OperatorSourceWeight**
  - `id`, `operator_id`, `source_id`, `weight`.
  - Настройка распределения трафика по операторам для конкретного источника.

Нагрузка оператора считается как количество активных обращений (`Contact.is_active = True`), где оператор назначен на контакт.

## Алгоритм распределения

При регистрации обращения:

1. **Определение лида**
   - По `external_lead_id` ищется существующий `Lead`.
   - Если не найден — создаётся новый.

2. **Выбор доступных операторов**
   - Из `OperatorSourceWeight` выбираются операторы, назначенные на источник.
   - Фильтрация по условиям:
     - оператор активен (`is_active = True`);
     - его текущая нагрузка `< load_limit`.

3. **Распределение по весам**
   - Для каждого подходящего оператора считаются:
     - текущее количество обращений по этому источнику;
     - отношение `обращения_по_источнику / weight`.
   - Выбирается оператор с **минимальным отношением** (наименьшее отклонение от желаемой доли). При равенстве берётся оператор с меньшим `id`.
   - Если подходящих операторов нет, обращение создаётся **без оператора** (`operator_id = null`).

4. **Создание обращения**
   - Создаётся запись `Contact`, связанная с лидом, источником и выбранным оператором (если найден).

Кратко:

- Один и тот же лид определяется по `external_id`.
- Вес оператора влияет на то, насколько часто он должен получать обращения данного источника.
- Лимит учитывается по количеству активных контактов, назначенных оператору.
- Если подходящих операторов нет, обращение сохраняется без оператора (это можно явно описать в ответе на тестовое как осознанный выбор).

## Запуск локально

Установить зависимости (включая dev-инструменты):

```bash
pip install -e .[dev]
```

Запустить приложение:

```bash
uvicorn app.main:app --reload
```

По умолчанию используется SQLite-файл `app.db` в корне проекта.

Документация OpenAPI доступна по адресу `http://127.0.0.1:8000/docs`.

## Тесты и статические проверки

- Запуск тестов с покрытием (порог настроен на 90%, текущее покрытие ~98%):

```bash
python -m pytest
```

- Проверка типов (strict):

```bash
python -m mypy app
```

- Линтер ruff:

```bash
python -m ruff check app tests
```

## Запуск в Docker

Сборка образа:

```bash
docker build -t lead-distribution-crm .
```

Запуск контейнера:

```bash
docker run --rm -p 8000:8000 lead-distribution-crm
```

После этого API будет доступно по адресу `http://127.0.0.1:8000`.

## Примерный сценарий использования API

1. Создать оператора: `POST /operators/`.
2. Создать источник: `POST /sources/`.
3. Настроить веса операторов для источника: `POST /sources/{source_id}/weights`.
4. Зарегистрировать обращение: `POST /contacts`.
5. Посмотреть лидов и их обращения: `GET /leads`.
6. Посмотреть агрегированную статистику распределения: `GET /stats/distribution`.
